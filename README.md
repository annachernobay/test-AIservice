Інструкція із запуску

### 1. Клонування репозиторію та підготовка

# Клонуйте репозиторій (замініть посилання на своє)
git clone [https://github.com/ваш_логін/назва_репозиторію.git](https://github.com/ваш_логін/назва_репозиторію.git)
cd назва_репозиторію

# Створіть віртуальне середовище
python -m venv venv

# Активуйте його:
# Linux / macOS:
source venv/bin/activate
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Windows (CMD):
venv\Scripts\activate.bat

# Встановіть необхідні залежності
pip install -r requirements.txt


### 2. Налаштування змінних оточення

Створіть файл `.env` на основі шаблону:

cp .env.example .env


### 3. Запуск сервера

uvicorn main:app --reload

### 4. Перевірка роботи

Після запуску відкрийте у браузері:

* **Веб-чат (UI):** [http://127.0.0.1:8000](http://127.0.0.1:8000)
* **Документація Swagger API:** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

## 💾 База даних та ініціалізація

Проєкт використовує **SQLite** (`chat.db`). 
Автоматична ініціалізація таблиць відбувається під час першого запуску сервера завдяки виклику `models.Base.metadata.create_all()` у `main.py`. Окремі міграції або ручне виконання SQL-скриптів не потрібні.


## 📡 Приклади API-запитів (cURL)

### 1. Створення нової сесії

curl -X POST "[http://127.0.0.1:8000/sessions](http://127.0.0.1:8000/sessions)" \
     -H "Content-Type: application/json" \
     -d '{"model": "gpt-4o-mini"}'

### 2. Надсилання повідомлень у сесію

curl -X POST "[http://127.0.0.1:8000/sessions/](http://127.0.0.1:8000/sessions/){session_id}/messages" \
     -H "Content-Type: application/json" \
     -d '{"content": "Привіт! Напиши короткий факт про Python."}'



Свідомі компроміси

* **Відсутність керування контекстним вікном:** Сервіс надсилає всю історію сесії "як є", без встановлення ліміту повідомлень, обрізання за токенами (truncation) чи скочуваного вікна (sliding window).
* **Спрощена валідація моделей:** Перелік дозволених моделей не оновлюється динамічно з API провайдера (відсутня жорстка перевірка валідності назви моделі при створенні сесії).
* **База даних:** Використано **SQLite** замість PostgreSQL для простоти локального запуску без підняття додаткових контейнерів (Docker).
* **Відсутність потокового виводу (Streaming):** Відповіді від AI повертаються одним готовим JSON-об'єктом замість потокової передачі токенів через Server-Sent Events (SSE) або WebSockets.
