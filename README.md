# AI Chat Service

## Інструкція із запуску

### Швидкий запуск через Docker (Рекомендовано)

1. Переконайтеся, що файл `.env` створено у корені проєкту та в ньому вказано ключ `OPENROUTER_API_KEY`.
2. Запустіть сервіс однією командою:
```bash
docker compose up --build
```
1. Клонування репозиторію та підготовка (запуск через налаштування середовища Python)
Bash
git clone [https://github.com/ваш_логін/назва_репозиторію.git](https://github.com/ваш_логін/назва_репозиторію.git)
cd назва_репозиторію
Створіть та активуйте віртуальне середовище:

Bash
python -m venv venv
Linux / macOS: source venv/bin/activate

Windows (PowerShell): .\venv\Scripts\Activate.ps1

Windows (CMD): venv\Scripts\activate.bat

Встановіть необхідні залежності:

Bash
pip install -r requirements.txt
2. Налаштування змінних оточення
Створіть файл .env на основі шаблону:

Bash
cp .env.example .env
3. Запуск сервера
Bash
uvicorn main:app --reload
4. Перевірка роботи
Після запуску відкрийте у браузері:

Веб-чат (UI): http://127.0.0.1:8000

Документація Swagger API: http://127.0.0.1:8000/docs

Інструкція для швидкої перевірки endpoints:

Найпростіше перевірити через Swagger UI: http://127.0.0.1:8000/docs

POST /sessions — створити нову сесію (отримаєте session_id).

POST /sessions/{session_id}/messages — надіслати тестове повідомлення AI (перевірити відповідь моделі та підраховані токени/вартість).

GET /sessions/{session_id} (або /history) — перевірити, що історія діалогу та дані збереглися.

DELETE /sessions/{session_id} — перевірити видалення/очищення сесії.

База даних та ініціалізація
Проєкт використовує SQLite (chat.db).
Автоматична ініціалізація таблиць відбувається під час першого запуску сервера завдяки виклику models.Base.metadata.create_all() у main.py. Окремі міграції або ручне виконання SQL-скриптів не потрібні.

Приклади API-запитів (cURL)
1. Створення нової сесії:

Bash
curl -X POST "[http://127.0.0.1:8000/sessions](http://127.0.0.1:8000/sessions)" \
     -H "Content-Type: application/json" \
     -d '{"model": "gpt-4o-mini"}'
     
2. Надсилання повідомлень у сесію:

Bash
curl -X POST "[http://127.0.0.1:8000/sessions/](http://127.0.0.1:8000/sessions/){session_id}/messages" \
     -H "Content-Type: application/json" \
     -d '{"content": "Привіт! Напиши короткий факт про Python."}'
     
Свідомі компроміси
Відсутність керування контекстним вікном: Сервіс надсилає всю історію сесії "як є", без встановлення ліміту повідомлень, обрізання за токенами чи скочуваного вікна.

Спрощена валідація моделей: Перелік дозволених моделей не оновлюється динамічно з API провайдера (відсутня жорстка перевірка валідності назви моделі при створенні сесії).

Файлова база даних (SQLite): Використано SQLite для автономності та миттєвого запуску сервісу без необхідності розгортати й налаштовувати окремий контейнер бази даних (PostgreSQL/MySQL).
